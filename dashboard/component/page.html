    How it works

    Five core stages run once per second, followed by the v2 extensions. Select one to see what it does and the code behind it.

    Run it

    Use two terminals from the project folder: one for the governor, one for the dashboard.

    

    Run the governor with --dry-run first to log detections without changing any priority. On macOS, restoring a priority needs sudo. On Windows, open PowerShell as Administrator to manage processes you do not own.
    

    


    

    Evaluation
    

    Four measurements, each taken by a script in the project. The simulator above shows the same quantities for one generated run.
    

    

    Detection time
    Seconds from the start of an anomaly to the first throttle. Measured by benchmark.py.
    

    False alarms
    Anomaly episodes during normal use. Counted by report.py after a long dry run, adaptive against fixed threshold.
    

    Resource reduction
    CPU use of the offender before and after throttling, and how much a competing program recovers.
    

    Monitoring overhead
    CPU, memory and cycle time of the governor itself, logged every cycle.
